# Лабораторная работа №5 — элементы сетевого программирования

## Цель работы

Разработать клиент-серверное приложение на C++ с использованием Windows Sockets API (Winsock), TCP и собственного протокола кадрирования сообщений.

Приложение принимает произвольный текст от клиента, анализирует его на сервере и возвращает статистику.

## Вариант №15

Индивидуальный вариант — TCP-служба анализа текста.

Параметры варианта: `STUDENT_ID = 54`, `SEED = 6238`, `BASE_PORT = 20054`. Порт по умолчанию — `20054`.

Сервер вычисляет количество байтов, строк, слов, ASCII-цифр `0–9` и латинских букв `A–Z`, `a–z`.

## Архитектура решения

Решение `LR5_network` состоит из четырёх проектов Visual Studio:

| Проект | Назначение |
|---|---|
| `Common` | Статическая библиотека с анализатором текста, TCP-протоколом и логированием |
| `Server` | Многопоточный TCP-сервер |
| `Client` | Консольный TCP-клиент |
| `Tests` | Консольные модульные тесты |

Проекты `Server`, `Client` и `Tests` используют общую библиотеку `Common`. Сетевые проекты подключают `Ws2_32.lib`. Конфигурации включают `Debug` и `Release` для платформы `x64`.

В текущем окружении Visual Studio используется toolset `v145`, стандарт языка — C++17, Windows SDK — `10.0`.

Основные исходные файлы:

- `Common/TextAnalyzer.h/.cpp` — анализ текста;
- `Common/Protocol.h/.cpp` — передача кадров через TCP;
- `Common/Logger.h/.cpp` — журналирование событий;
- `Server/main.cpp` — запуск и обработка клиентов;
- `Client/main.cpp` — подключение и отправка текста;
- `Tests/main.cpp` — модульные проверки;
- `tests/test_client.py` — интеграционные проверки сетевого взаимодействия.

## TCP-протокол

TCP является потоковым протоколом, поэтому приложение использует собственное кадрирование:

```text
[4 байта — длина полезной нагрузки в network byte order]
[N байт — полезная нагрузка]
```

Перед отправкой длина преобразуется функцией `htonl()`, после получения — `ntohl()`.

Максимальный размер полезной нагрузки — `65536` байт. Допускается пустая полезная нагрузка с длиной `0`.

В `Common` реализованы `SendAll()`, `RecvAll()`, `SendFrame()`, `RecvFrame()` и `SetSocketTimeouts()`. Сервер обслуживает каждого клиента в отдельном потоке.

## Алгоритм анализа текста

Количество байтов определяется размером исходной строки `std::string`, поэтому для UTF-8 учитываются фактические байты.

- `\n` увеличивает количество строк;
- пустой текст содержит `0` строк;
- если текст не заканчивается на `\n`, последняя строка учитывается;
- слово — непрерывная последовательность ASCII-букв и ASCII-цифр;
- пробелы, дефисы, пунктуация и другие символы разделяют слова;
- ASCII-цифры и латинские буквы считаются отдельно;
- байты UTF-8 кириллицы не считаются латинскими буквами и не входят в слова.

Для строки `Abc  123 x-y\nZ9` ожидается:

```text
bytes=15
lines=2
words=5
digits=4
latinLetters=6
```

## Открытие и сборка решения

Откройте `LR5_network.sln` в Visual Studio, выберите конфигурацию `Debug` или `Release` и платформу `x64`, затем выполните `Build Solution`.

Из Developer PowerShell сборка выполняется командами:

```powershell
msbuild LR5_network.sln /m /p:Configuration=Debug /p:Platform=x64
msbuild LR5_network.sln /m /p:Configuration=Release /p:Platform=x64
```

Ожидаемые исполняемые файлы находятся в `bin/x64/Debug/` и `bin/x64/Release/`.

## Запуск сервера

Сервер по умолчанию слушает `127.0.0.1:20054`:

```powershell
bin\x64\Debug\Server.exe
```

Поддерживаются параметры `--host HOST` и `--port PORT`:

```powershell
bin\x64\Debug\Server.exe --host 127.0.0.1 --port 20054
```

Для остановки сервера используется `Ctrl+C`.

## Запуск клиента

Перед запуском клиента сервер должен быть запущен. Текст можно передать аргументом:

```powershell
bin\x64\Debug\Client.exe --host 127.0.0.1 --port 20054 --text "Hello 123"
```

Или прочитать файл в бинарном режиме:

```powershell
bin\x64\Debug\Client.exe --host 127.0.0.1 --port 20054 --file input.txt
```

Клиент принимает ровно один из параметров `--text` или `--file`. Размер сообщения не должен превышать `65536` байт. Ответ выводится в формате:

```text
bytes=9
lines=1
words=2
digits=3
latinLetters=5
```

## Модульные тесты

Запуск модульных тестов проекта `Tests`:

```powershell
bin\x64\Debug\Tests.exe
```

Проверяются пустой текст, пробелы, слова, цифры, пунктуация, несколько строк, завершающий перевод строки, кириллица, смешанный текст, максимальный размер кадра и ошибки протокола. Тесты выводят ожидаемые и фактические значения и итоговую сводку `PASS`/`FAIL`.

## Интеграционные тесты

`tests/test_client.py` использует стандартные модули Python: `socket`, `struct`, `subprocess`, `threading` и `unittest`.

Запуск с автоматическим стартом сервера:

```powershell
python tests\test_client.py --server bin\x64\Debug\Server.exe
```

Проверяются обычный и пустой запросы, пробелы и переводы строк, кириллица, размеры `1`, `100`, `1000` и `65536` байт, раздельная отправка заголовка и полезной нагрузки, частичное чтение ответа и три одновременных подключения.

Если сервер уже запущен, используется режим:

```powershell
python tests\test_client.py --reuse-server --host 127.0.0.1 --port 20054
```

На этапе 7 тесты были запущены против `bin/x64/Debug/Server.exe`: выполнено 8 тестов, результат — `OK`.

## Эксперименты и графики

Скрипты экспериментов и построения графиков относятся к следующим этапам работы:

- `scripts/run_experiments.py` — измерение времени обмена для сообщений размером 100, 1000 и 10000 байт с минимум тремя повторами;
- `scripts/plot_results.py` — построение графиков задержки и пропускной способности;
- `data/experiments.csv` — результаты измерений.

До фактического запуска экспериментов нельзя указывать измеренные значения или строить графики по искусственным данным.
